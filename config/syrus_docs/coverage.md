# Coverage Reporting

Syrus can parse test coverage artifacts produced by graders, compute PR-level diff coverage, optionally block workflows on threshold misses, and post a coverage summary comment on the PR.

## Enabling coverage

Configure coverage in `.syrus.yml`:

```yaml
coverage:
  sources:
    - artifact: coverage/lcov.info
      format: lcov
  threshold:
    lines: 80
    pr_lines: 70
  on_miss: warn
  pr_comment: true
  hitmap_ttl_days: 7
```

Your grader command must produce the artifact at the path listed under `sources[].artifact` (relative to the repo root).

## Sources

Each entry under `sources` names a coverage artifact and its format:

| Field | Required | Values |
|---|---|---|
| `artifact` | yes | Path relative to repo root |
| `format` | yes | `lcov` or `cobertura` |

Multiple sources are merged before threshold evaluation. Use multiple sources when different test suites produce separate reports (e.g., unit tests in lcov + integration tests in Cobertura).

## Thresholds

| Field | Meaning |
|---|---|
| `threshold.lines` | Minimum overall line coverage percentage (0–100) |
| `threshold.pr_lines` | Minimum line coverage on lines changed in this PR (0–100) |

Omit a threshold field to skip that check. Both thresholds are evaluated together; a miss on either triggers `on_miss` behavior.

## on_miss

What Syrus does when coverage falls below the threshold:

| Value | Behavior |
|---|---|
| `warn` (default) | Logs a warning; workflow continues |
| `block` | Fails the `coverage_analyze` step; agent must add tests |
| `schedule` | Triggers a follow-up coverage-fix Job |

## pr_comment

When `pr_comment: true`, Syrus posts a formatted coverage summary as a PR comment after the `coverage_analyze` step. The comment includes overall line coverage %, PR-diff coverage %, and per-file breakdown.

## hitmap_ttl_days

How long the hit-map blob (per-file line hit data) is retained. Default: 7 days. `CoverageHitMapPruneJob` cleans up expired blobs. The coverage summary artifact and PR annotations persist indefinitely; only the raw hit-map blob is pruned.

## How coverage flows through the workflow

1. Graders run and produce coverage artifacts in the workspace.
2. `coverage_analyze` (non-agentic) parses them, merges multiple sources, annotates the PR diff, evaluates thresholds, and stores results as `workflow.artifacts["coverage"]`.
3. `coverage_pr_comment` (non-agentic) posts the PR comment if configured.
4. The `CoverageSnapshot` model stores a per-SHA summary for trend tracking.

## Formats

### lcov

Standard lcov format (`coverage/lcov.info`). Generated by most Ruby (SimpleCov), JavaScript (Istanbul/c8/nyc), and Go (go test -coverprofile) test runners.

### Cobertura

XML-based format (`coverage/cobertura.xml`). Generated by pytest-cov (Python), JaCoCo (Java), and many CI systems' built-in coverage reporters.

## Coverage in the spending insights

Coverage data is stored per-workflow and per-SHA in `CoverageSnapshot`. It is not currently surfaced in the spending insights UI, but the snapshots are available via the Rails console for trend queries:

```ruby
CoverageSnapshot.where(repository: repo).order(:created_at).pluck(:sha, :lines_pct)
```
